# DotEngine — концепт проекта

> Этот документ — конспект обсуждения идеи движка (зафиксировано из чата с AI-коллегой Zolopababara).

## Что это

**DotEngine** — Android-приложение: **настоящий 3D-движок**, который рисует картинку **ASCII-символами (в цвете)** внутри терминал-подобного интерфейса. 3D считается софтверным рендером (raycast/растеризация по треугольникам), поддерживает загрузку моделей.

- Аккаунт: `Kolya2010228` (Svojov), репозиторий приватный.
- Package: `dot3d`.

## Стек

- **Java + Gradle** (по образцу проекта Jopatok — минимум зависимостей, быстрый предсказуемый билд).
- **minSdk 24 / targetSdk 34.**
- Приоритет — **максимальная производительность и простота**.

## Рендеринг (ASCII)

- Один полноэкранный `SurfaceView` с выделенным render-потоком.
- Глифы ASCII (0x20–0x7E) один раз растеризуются в offscreen-атлас; кадр собирается из заранее отрисованных глифов (НЕ по одному `drawText` на ячейку) → высокий FPS даже при крупной сетке.
- Цвет — на символ (тонирование глифа).
- Яркость пикселя/семпла кодируется символом из палитры (от тёмного к яркому).

## Терминал

- Стартовый экран — **функциональный терминал**: моноширинный вывод + поле ввода команд.
- Неизвестные / «ненастоящие» команды дают правдоподобный ответ-заглушку, но реально работают только нужные:
  - `run` / `start` — запуск движка.
  - `grid <W> <H>` — размер сетки символов **до старта**, **сохраняется** (SharedPreferences).
  - `palette <name|chars>` — палитра яркости (пресеты + произвольная строка символов), сохраняется.
  - `load <file>` — выбрать/загрузить модель (без аргумента — системный пикер).
  - `seed <n>` — зерно бесконечного мира (опционально), сохраняется.
  - вспомогательные: `help`, `clear`, `set color on/off`, `ls`.
- **Тач-нюансы:** вывод рисуется вручную (не `TextView`), поэтому долгое нажатие **не выделяет и не копирует** символы. Ввод — отдельное скрытое поле только для набора команд.

## 3D (именно настоящее 3D)

- Не классический 2.5D-raycaster по стенам, а **софтверный рендер по треугольникам**:
  - сцена = набор треугольников (модели + геометрия мира);
  - на каждую символ-ячейку — луч/семпл, поиск ближайшего треугольника через глубинный буфер;
  - освещённость (нормаль + расстояние) → выбор ASCII-символа по яркости; цвет — из материала/нормали.
- Настоящая перспектива, повороты по осям, работа с произвольными мешами.
- Производительность держится за счёт низкого «разрешения» (сетка символов = главный буфер).

## Загрузка моделей из файла

- Формат: **OBJ** (`.obj`) — текстовый, простой, повсеместный. Парсим `v`, `f`, опц. `vn`.
- Источники:
  - встроенные ассеты `app/src/main/assets/models/*.obj` (демо-модели), `ls` перечисляет, `load <name>` грузит;
  - открытие `.obj` с устройства через Storage Access Framework (команда `load` без аргумента → системный пикер).

## Физика и тестовый уровень

- **Гравитация:** у игрока вертикальная скорость, постоянное ускорение `g` вниз, прыжок = импульс вверх, приземление на верхнюю грань куба останавливает падение и разрешает новый прыжок.
- **Коллизии:** игрок как AABB/точка+радиус против ближайших кубов (проверяются только соседние ячейки — дёшево). Можно стоять на кубах и падать в проёмы.
- **Тестовый уровень = бесконечный мир из кубов:**
  - процедурная генерация по чанкам (напр. 16×16 по X/Z), генерация при приближении и выгрузка при удалении;
  - наличие/высота куба детерминированы из координат (хеш / value-noise) с фиксированным `seed` → мир воспроизводим и бесконечен в обе стороны (воксельный ландшафт из кубов);
  - на кадр рендерятся только треугольники видимых ближних чанков.

## Управление

- **Левая половина экрана** — виртуальный джойстик (ходьба: вперёд/назад/стрейф), появляется под пальцем.
- **Правая половина** — drag для поворота камеры (yaw/pitch) + **кнопка прыжка** (в углу правой части).
- Мультитач: левая и правая зоны независимы (можно идти и крутить камеру одновременно).

## Меню паузы

- Во время работы движка системная кнопка **«Назад»** не закрывает приложение, а ставит игру на паузу и открывает **overlay-меню** поверх рендера.
- В меню — **настройки текущей сессии** (применяются на лету): размер сетки, палитра / цвет, чувствительность поворота, FOV, дальность прорисовки (render distance), `seed` мира.
- Пункты: **Continue** (вернуться в игру) и **Exit to terminal** (остановить движок, вернуться в терминал).
- Логика «Назад»: в меню → ещё раз «Назад» = Continue; в терминале → «Назад» = обычный выход/сворачивание.
- Общие настройки (`grid`, `palette`, `seed`) синхронизированы между терминалом и меню и одинаково сохраняются.
